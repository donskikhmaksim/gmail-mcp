# ТЗ-аддендум: Telegram Mini App для automation_key (поверх кнопочной версии)

**Статус:** уточнение владельца 2026-08-11, поверх `docs/TZ_automation_key_hub.md` (уже реализовано и в проде — кнопочная версия в `src/automation_key.ts`).

## Зачем

Владелец: «можно через мини апп тоже сделать выбор, там галочки проще
тыкать». Кнопочная версия (toggle через редактирование inline-кнопок)
УЖЕ полностью рабочая и в проде — Mini App ДОБАВЛЯЕТСЯ как второй, более
удобный способ того же самого действия, не заменяет первый.

## Что такое Mini App здесь

Веб-страница, которую Telegram открывает поверх чата (кнопка с
`web_app: {url: ...}`). Страница использует Telegram WebApp JS SDK
(`https://telegram.org/js/telegram-web-app.js`, подключается тегом
`<script>`, без npm-пакета — это просто глобальный `window.Telegram.WebApp`).

## Механизм

### 1. Отдача страницы

Новый роут в `src/http.ts` (по образцу уже существующего `/dashboard/:secret`
— посмотри его реализацию перед тем как писать новый) — например
`GET /automation-key-app`. Отдаёт ОДИН статический HTML-файл (инлайн в коде
роута или отдельный файл в `src/` — смотри по месту, что здесь принято для
`/dashboard`) с:
- 6 чекбоксов (по одному на `gmail`/`calendar`/`drive`/`sheets`/`docs`/`ticktick`,
  подписи — человеческие имена сервисов), чекбокс «Все сразу» (переключает
  остальные 6 разом, не независимая опция);
- кнопкой «Получить ключ»;
- минимальной стилизацией под тему Telegram (`Telegram.WebApp.themeParams`
  — необязательно детально, но хотя бы не белый текст на белом фоне в
  тёмной теме — используй `Telegram.WebApp.colorScheme`/CSS-переменные
  `--tg-theme-*`, которые сам SDK прокидывает).

Страница НЕ требует авторизации на GET (сама разметка — не секрет), но
экшен «Получить ключ» — требует.

### 2. Точка входа — кнопка в существующем меню

В уже существующем ответе на `/automation_key` (кнопочное меню, см.
`src/automation_key.ts`, там где строится `reply_markup` с 8 кнопками)
добавить ЕЩЁ ОДНУ кнопку — `{"text": "Открыть как мини-апп", "web_app":
{"url": "<PUBLIC_BASE_URL>/automation-key-app"}}`. `PUBLIC_BASE_URL` — найди,
как уже вычисляется публичный адрес сервиса в этом репозитории (искать
`RAILWAY_PUBLIC_DOMAIN`/`PUBLIC_BASE_URL` в `src/`) — не хардкодить домен.

### 3. Отправка выбора обратно на сервер — БЕЗ `web_app_data`

НЕ используй `Telegram.WebApp.sendData(...)` (это шлёт `web_app_data` апдейт
через бот-вебхук — потребовало бы менять `allowed_updates` и городить ещё
один тип апдейта). Вместо этого: страница делает обычный `fetch(...)` POST
ПРЯМО на новый backend-роут этого же сервера (например
`POST /automation-key-app/generate`), в теле — отмеченные сервисы И
`Telegram.WebApp.initData` (сырая строка, которую даёт сам SDK —
`window.Telegram.WebApp.initData`).

### 4. Проверка `initData` — ОБЯЗАТЕЛЬНО, это единственная защита

Backend-роут ОБЯЗАН проверить подлинность `initData` (стандартный алгоритм
Telegram: `https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app`
— HMAC-SHA256 самой строки `initData` (без поля `hash`, поля отсортированы и
склеены через `\n`) с ключом `HMAC-SHA256(bot_token, "WebAppData")`,
сравнение с полем `hash` из `initData` — **постоянное время**
(`crypto.timingSafeEqual`, тот же принцип, что и у `secretTokenMatches` в
`src/tg_approval.ts`, посмотри её реализацию для образца)). Отдельно
проверить `auth_date` не старше разумного окна (например 5 минут — Telegram
сам не гарантирует свежесть, это ответственность бэкенда) — иначе `initData`
можно переиграть (replay) сколь угодно долго после того, как страница была
открыта.

После проверки подписи — распарсить `user` из `initData` (JSON внутри
одного из полей) и убедиться, что `user.id` (в виде строки) СОВПАДАЕТ с
`cfg.ownerChatId` — та же owner-only дисциплина, что везде в этом файле,
никакого нового пути авторизации не изобретаем, только другой источник
личности пользователя (подписанные данные Telegram вместо `callback_query.
from.id`).

Без валидного `initData` или без совпадения владельца — 403, ничего не
генерировать.

### 5. Генерация и доставка ключа

После успешной проверки — та же логика генерации, что уже есть в
`src/automation_key.ts` (переиспользовать существующие функции создания
окна/маски scope, не дублировать), НО токен **не показывается на самой
странице мини-аппа** — показывается ЧЕРЕЗ ОБЫЧНОЕ СООБЩЕНИЕ В ЧАТЕ, тем же
путём и с тем же 10-секундным самоудалением, что и у кнопочной версии
(переиспользовать, не копировать код). Страница мини-аппа в ответ на успех
просто показывает "Готово — ключ отправлен в чат, исчезнет через 10с" и
закрывается (`Telegram.WebApp.close()`, необязательно — можно оставить
открытой с этим текстом, решай по месту, что удобнее).

Причина не показывать сырой токен прямо на странице: единый путь
доставки/аудита секрета (одно место в коде решает «как токен появляется
у владельца»), а не два параллельных с разным поведением (например разным
временем самоудаления).

### 6. Пустой выбор

Тот же случай, что в кнопочной версии — если ни один сервис не отмечен,
"Получить ключ" на странице должен быть либо задизейблен (JS), либо backend
отвечает ошибкой без создания записи — не полагаться только на фронтенд-
проверку (тот же fail-closed принцип).

## Тестовый план

1. `initData` без валидной подписи (испорченный/поддельный hash) → 403,
   ничего не создано.
2. `initData` с валидной подписью, но `user.id` ≠ владелец → 403, ничего не
   создано.
3. `initData` с `auth_date` старше окна свежести → 403 (replay-защита).
4. Валидный `initData`, один отмеченный сервис → окно создано с этим scope,
   ТОТ ЖЕ формат, что у кнопочной версии (проверить через прямое чтение
   таблицы/`listActiveWindows` в тесте).
5. Валидный `initData`, «Все сразу» → `scope='all'`.
6. Пустой выбор → ничего не создано, backend отвечает ошибкой.
7. Токен уходит в чат ОБЫЧНЫМ сообщением с тем же 10-секундным
   самоудалением, что у кнопочной версии (не показывается в теле ответа
   backend-роута мини-аппа).
8. GET-роут страницы отдаёт HTML без авторизации (сама разметка не секрет),
   200 OK.

## Явно НЕ входит

- Замена кнопочной версии — обе точки входа работают параллельно, кнопочная
  не убирается.
- Стилизация под полноценный дизайн — минимальная, читаемая, тема Telegram
  через CSS-переменные, не более.
- Порт Mini App на другие сервисы — она физически может жить только там,
  где вебхук/публичный URL (gmail-mcp), это не меняется этим ТЗ.
